## dow_trend の処理順（各確定足）
1. その足で確定/移動したピボットを反映
2. 遅れて確定した押し安値（直近ブレイク区間内のもの）を採用
3. 終値が押し安値/戻り高値を抜けたら転換
4. 終値が直前の高値（安値）を抜けたらブレイク → 間の最新の安値（高値）を押し安値（戻り高値）に

## 仮決め（ユーザー確認待ち）
- D1 押し安値の価格は採用時点で固定（そのピボットが後で移動しても線は動かさない）
- D2 「更新すべき高値」＝前回ブレイク済み高値より上の確定高値のうち最高値
- D3 ✅確定(2026-10-18)：ブレイク時の押し安値＝間にある**最新**の安値（最高値に一番近い安値）
- D4 ✅確定(2026-10-18 ユーザー回答)：転換直後の戻り高値（押し安値）＝割れた押し安値（戻り高値）以降で**最新**の確定高値（安値）＝ブレイクの起点。未確定ならヒゲ最高値で仮置き
  - 例：2026-03 下降転換 → 戻り高値 1.1928（2月）、2025-09 上昇転換 → 押し安値 1.1574、2025-10-09 に実体で割れて下降転換
- D5 転換直後の「次に抜くべき安値」は、割った押し安値より下にあるものだけ

## 方針（ユーザー合意）
高値安値の検出（pivots.py, ATRルール）は後で差し替え・最適化できる部品。先に「どこを押し安値と見るか」のロジック（dow_trend.py）を固める。

## 仮トレンド（実装 2026-10-18, DOW_RULES §3）
主要トレンドと同じルールの2台目のステートマシン＋開始パターン：
- 仮上昇開始：確定 H1,L1,H2,L2 で L2>L1、H1を終値で上抜け済み → 終値がH2を上抜けた足で開始、仮の押し安値=L2（下降は対称）
- 以降の押し安値の移動・転換は主要と同じ（仮の押し安値を終値で割ると仮転換）
- 例：H4 2026-07-16〜 主要=下降のまま 仮=上昇

## Wトップ/ボトム（実装 2026-10-18, DOW_RULES §4）
主要上昇中に確定 A高値・B安値・C高値、AからCまでAのヒゲを終値で上抜けなし → 終値がBを割った足で Wトップ（B=水平帯の候補）。下降は対称。主要トレンド1区間につき最大2回。主要転換と同じ足でも両方記録。
- A とCの高さの許容差：設けない（ユーザー確認 2026-10-18）

## 水平帯（実装 2026-10-18, DOW_RULES §5, `zones.py`）
- 元になるもの：主要転換で割れた押し安値/戻り高値、仮トレンド転換、Wのネック(B)
- 外側＝ピボットのヒゲ先、内側＝その波（前後の反対ピボットの間、有効化時点までの足）で最もヒゲ寄りの実体端
- 有効化＝ブレイクした足（それ以前は見えない）、チャートでは起点から描画（有効化前は点線）
- 失効（Z1・仮決め）：有効化時に価格が帯の下にあれば、後の足の実体全体が帯の上に出た足で終了（逆も同様）。有効化足では終了しない
- 同じピボット由来は1本にまとめてラベルを併記（例：押し安値・仮押し安値）
- `zones.active_asof(zones, k)`：足kの終値時点でEAが使える帯

## トレンドライン寿命管理（実装 2026-10-18, `lines.py`）
線の生成は既存 `chart_lab/trendline_causal_engine.py`（3点ライン生成時に落ちるバグを修正）。消去ルール：
1. ブレイク＋2ピボット：上昇ラインを終値で下抜け → ブレイク後にできたダウ高値が2つ確定したら消去（下降ラインは対称）。終値が線の内側に戻ったらカウントをリセット
2. 推進ラインは主要トレンド転換で消去。調整ラインは転換で推進に変わり残る
3. 線の作り直しが不成立になった場合（ピボット移動など）も消去
✅確定(2026-10-18)：L1 ブレイク前にできた高値は数えない／L3 線の形が修正されたらブレイク状態をリセット。仮決め：L2 線ちょうどの終値は内側扱い
- `lines.active_asof(result, k)`：足k時点でEAが使える線（その時点の形で計算）
